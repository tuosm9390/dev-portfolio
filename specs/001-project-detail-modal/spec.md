# Feature Specification: Project Detail Modal

**Feature Branch**: `001-project-detail-modal`  
**Created**: 2026-03-23  
**Status**: Draft  
**Input**: User description: "프로젝트 카드 자세히보기 클릭 시 모달로 프로젝트 내용을 표시할 수 있게 해줘. 이때 모달이 버벅이지 않도록 설정에 유의해서 작업해줘."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 프로젝트 상세 정보 확인 (Priority: P1)

방문자가 프로젝트 카드의 '자세히 보기' 버튼을 클릭하여 해당 프로젝트의 구체적인 내용(상세 설명, 기술 스택 등)을 모달 창을 통해 확인합니다.

**Why this priority**: 포트폴리오의 핵심 가치는 프로젝트의 상세 내용을 효과적으로 전달하는 것이며, 모달은 페이지 이동 없이 맥락을 유지하며 정보를 제공하는 가장 중요한 수단입니다.

**Independent Test**: 특정 프로젝트 카드의 '자세히 보기'를 클릭했을 때, 해당 프로젝트의 데이터가 정확히 포함된 모달이 화면에 즉시 표시되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 프로젝트 목록 화면에서, **When** '자세히 보기' 버튼을 클릭하면, **Then** 해당 프로젝트의 상세 내용이 포함된 모달이 나타난다.
2. **Given** 모달이 열린 상태에서, **When** 닫기 버튼 또는 배경(Overlay)을 클릭하면, **Then** 모달이 닫히고 원래 보던 목록 위치로 돌아온다.

---

### User Story 2 - 부드럽고 쾌적한 사용자 경험 (Priority: P2)

모달이 열리고 닫힐 때 끊김 없는(Lags-free) 애니메이션을 제공하며, 대용량 이미지나 복잡한 레이아웃에서도 성능 저하 없이 반응해야 합니다.

**Why this priority**: 사용자가 명시적으로 '버벅이지 않도록' 요청했으므로, 시각적 완성도와 성능 최적화는 이 기능의 핵심 요구사항입니다.

**Independent Test**: 저사양 기기나 모바일 환경에서도 모달 오프닝/클로징 애니메이션이 프레임 드롭 없이 부드럽게 동작하는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 모달 호출 시, **When** 애니메이션이 진행되는 동안, **Then** 화면이 멈추거나 버벅이는 현상 없이 부드럽게 전환된다.
2. **Given** 모달 내에 이미지가 로드될 때, **When** 레이아웃 시프트(Layout Shift)가 발생하는지 확인하며, **Then** 이미지 로딩 중에도 UI 반응성이 유지된다.

---

### User Story 3 - 프로젝트 링크 연결 및 탐색 (Priority: P3)

모달 내에서 프로젝트의 실제 서비스(Live URL)나 소스 코드(GitHub)로 바로 이동할 수 있는 링크를 제공합니다.

**Why this priority**: 프로젝트 확인 후 다음 행동(서비스 접속 또는 코드 확인)으로 유도하는 필수적인 전환 단계입니다.

**Independent Test**: 모달 내 링크 버튼들이 정확한 목적지로 연결되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 모달이 열린 상태에서, **When** 'Live Demo' 또는 'GitHub' 링크를 클릭하면, **Then** 새 탭에서 해당 페이지가 정상적으로 열린다.

---

### Edge Cases

- **데이터 부재**: 프로젝트 데이터 중 일부(예: githubUrl)가 없는 경우 해당 UI 요소가 어색하지 않게 숨겨지거나 대체되는가?
- **긴 텍스트**: 프로젝트 상세 설명이 매우 길어질 경우 모달 내에서 스크롤이 부드럽게 동작하며 전체 UI가 깨지지 않는가?
- **뒤로가기 조작**: 모달이 열린 상태에서 브라우저 '뒤로가기' 클릭 시 모달만 닫히도록 URL 해시 또는 쿼리 파라미터(예: ?project=id)와 연동하여 브라우저 히스토리를 관리한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 프로젝트 카드의 '자세히 보기' 클릭 시 고유 ID에 해당하는 프로젝트 데이터를 모달에 바인딩해야 한다.
- **FR-002**: 모달은 화면 중앙에 배치되어야 하며, 모바일 환경에서는 화면 크기에 맞게 최적화된 레이아웃을 제공해야 한다.
- **FR-003**: 모달의 배경(Overlay)은 어둡게 처리되어 콘텐츠 집중도를 높여야 한다.
- **FR-004**: 사용자는 'ESC' 키를 눌러 모달을 닫을 수 있어야 한다.
- **FR-005**: 모달 내에는 제목, 요약, 상세 설명, 기술 스택(태그 형태), 이미지, 외부 링크 버튼이 포함되어야 한다.
- **FR-006**: 모달의 열림/닫힘 상태는 각 프로젝트 카드 컴포넌트 내에서 관리하되, 성능 최적화를 위해 렌더링 시점에 데이터를 주입하며 모달 UI 자체는 포털(Portal) 등을 사용하여 독립적으로 렌더링한다.
- **FR-007**: 성능 최적화를 위해 모달 애니메이션은 GPU 가속을 활용하는 라이브러리(Framer Motion 등)를 사용해야 한다.
- **FR-008**: 프로젝트 상세 설명은 마크다운(Markdown) 형식을 지원하여 리스트, 강조 등 풍부한 텍스트 표현이 가능해야 한다.

### Key Entities

- **Project**: 포트폴리오의 각 프로젝트 정보 (ID, 제목, 설명, 이미지 경로, 기술 스택 리스트, URL 등 포함)
- **ModalState**: 현재 어떤 프로젝트가 선택되었는지와 모달의 가시성 여부를 추적하는 상태 (URL 쿼리와 동기화됨)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 모달 오픈 시 애니메이션 프레임이 60fps를 유지하며 체감되는 지연 시간이 100ms 이내여야 한다.
- **SC-002**: 모달 내 모든 이미지와 텍스트가 렌더링 완료되는 시점까지 레이아웃 깨짐이 없어야 한다.
- **SC-003**: Lighthouse 성능 점수에서 접근성(Accessibility) 항목 90점 이상을 유지해야 한다 (모달 포커스 트래핑 등 포함).
- **SC-004**: 마크다운으로 작성된 상세 설명이 스타일 깨짐 없이 올바르게 렌더링되어야 한다.

### Assumptions

- 현재 프로젝트 데이터 구조(`src/data/projects.ts`)를 그대로 사용하며, 모달용 추가 필드는 필요하지 않다고 가정한다.
- 애니메이션 라이브러리는 프로젝트에 이미 설치된 `framer-motion`을 활용한다.
